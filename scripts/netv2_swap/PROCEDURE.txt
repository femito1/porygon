HOW IT WORKS
  Phase 1 (each job's INLINE_CMD, run by nv2_pause at the restart in place, trainer stopped): copy the lineage's
    just-saved local state (final_model.pt with optimizer + counters, best / ema, train.log, GUARD_TRIPPED if any,
    pool incl. pool/frozen) to <handover>.tmp, cmp-check final_model.pt, compare the pool / frozen counts, write
    HANDOVER.txt (counters + last 'upd' line) and DONE (summary + md5), then mv -T <handover>.tmp <handover> (only if
    absent). Any failure: $S/FAIL-<run> and a STATE line; nothing else. Phase 1 NEVER touches MODE.
  Phase 2 (nv2_swap in netv2.env, right after nv2_pause, at every (re)start of r1 / g9, also in a fresh job): if no
    $S/DECISION exists and this side's handover is DONE (or any FAIL-* exists), wait <= 2 h (240 x 30 s; train.log
    touched every poll, so the 45-min stall watchdog never fires) for the other side's DONE / a FAIL / a DECISION;
    then propose COMMIT (both DONE, no FAIL) or ABORT (anything else) by hard-linking a temp file to $S/DECISION:
    the FIRST writer wins and both sides act on the file's content, never on their own proposal.
    COMMIT is applied once per run (runs/RUN/SWAP_APPLIED): r1 MODE g9p -> g9q, g9 MODE g9q -> g9p2; the handed-over
    lineage's local GUARD_TRIPPED (if any) is renamed .handed-over-<time> (it travelled with the handover).
    ABORT: nothing changes: each job resumes its own lineage from its own local save (MODE untouched).
  New modes' first start (r1 g9q: marker runs/r1/G9Q_A30_STARTED; g9 g9p2: runs/g9/G9P_A16_STARTED) happens only if
    DECISION = COMMIT and the handover it starts from has DONE + final_model.pt; otherwise the job's previous
    lineage continues (G9p on the A30, G9q on the A16) and a line "MODE ... but no committed ... handover" is logged.
  Fresh jobs (requeue / successor): a COMMIT the predecessor never applied is applied at the first source; a side
    whose handover is DONE but has no decision yet waits / decides at its first source as above.

STATE TABLE (read from files only; nothing to do unless marked ACTION)
  no $S                                   not armed.
  $S, INLINE_CMD in runs/RUN              armed, that job has not restarted yet (restart flag + SIGINT pending).
  runs/RUN/INLINE_CMD.running             phase 1 running in that job (a <handover>.tmp may be growing).
  <handover>/DONE, no DECISION            that side waits <= 2 h for the other (STATE "phase1 DONE" time + 2 h).
  FAIL-<run>                              phase 1 failed there (see runs/RUN/inline-<time>.log): ABORT follows at once.
  DECISION ABORT                          final for this attempt: both jobs train their own lineages; MODE unchanged.
  DECISION COMMIT, SWAP_APPLIED in 0-2    each run applies it at its next (re)start or in its next fresh job.
  COMMIT + 2 x SWAP_APPLIED + 2 x STARTED done.

RECOVERY
  * Agent / orchestrator died mid-swap: read the table above. The jobs resolve every state by themselves; never
    delete DONE, a handover dir or DECISION while a job may still read them.
  * A job died or was requeued after its phase 1 DONE but before a DECISION: the other side decides at its
    timeout or at once (if both DONE: COMMIT); the dead side's requeue / successor applies the DECISION at its first
    source (or waits / decides itself if there is none yet). No ACTION.
  * The other side is known to be gone for good and one job is waiting idle (no DECISION): ACTION (stops the wait
    early; only while DECISION is absent: ln fails otherwise, which is the point):
      echo "ABORT by operator $(date -u +%FT%T)" > $S/.op && ln $S/.op $S/DECISION; rm -f $S/.op
  * Both jobs died after COMMIT before applying it: their successors apply it at the first source (the MODE flip
    and the "first start" line show in their train.log). No ACTION.
  * Phase 1 FAIL / ABORT and you want to retry: once both jobs train again (their own lineages), archive the attempt:
      t=$(date -u +%m%d-%H%M); mv $S $S.abort-$t
      for h in runs/g9q/handover-a30 runs/r1/handover-g9p-a16; do for x in $C/$h $C/$h.tmp; do [ -e $x ] && mv $x $x.abort-$t; done; done
    (an ABORT writes no SWAP_APPLIED / STARTED marker: check none exists), then ARM AND GO again.
  * The trainer crashes in a new lineage's first start after COMMIT: a restart in place resumes the handover again
    (STARTED exists, no own final_model.pt yet -> --resume <handover>/final_model.pt); a fresh job resumes that
    lineage's newest mirrored file (the other side's pre-swap mirror = the handover state). No ACTION beyond the usual.
  * Never "swap back" by editing MODE: the old lineage dirs are stale (the lineage would fork). A swap back is a new
    swap with new handover dirs (a netv2.env change).

DON'TS
  * Do not edit netv2.env from the SIGINT until both relaunch lines appeared (both jobs inside nv2_pause / nv2_swap).
  * Do not arm with netv2.env v8 (it has no phase 2: the copies would be made and nothing would ever decide; harmless
    but a wasted restart).
  * Do not re-use a handover dir or $S from an earlier attempt (phase 1 refuses an existing handover dir -> FAIL ->
    ABORT; it refuses to start at all once a DECISION exists).

RESIDUAL RISKS
  * DECISION is a hard link on NFS (atomic on the server). If NFS refuses every write for a side (3 tries), that
    side proceeds without a decision = no flip; if the other side then writes COMMIT, the first side follows it only
    at its next restart, so both would train its old lineage meanwhile. Requires a broken /vol/bitbucket.
  * The 2-h wait idles a GPU when the other side never answers (by design; operator ABORT above shortens it).
  * A pool-trip HOLD on one side delays that side's phase 2 (<= 4 h): the other side ABORTs after 2 h and the held
    side follows the ABORT afterwards (consistent; only time lost).
